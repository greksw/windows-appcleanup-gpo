# Windows AppCleanup GPO — безопасная очистка Appx-приложений

[English](README.md) · [История изменений](CHANGELOG.ru.md) · [Инструкция GPO](docs/gpo-setup.ru.md)

Практический проект инвентаризации и удаления выбранных **Appx-приложений текущего пользователя** в Windows 10/11 через **User Configuration GPO → сценарий входа → PowerShell 5.1**. Основа проекта — предоставленные операционные версии v1.0, v1.3, v1.4 и три соответствующие CMD-обёртки.

**Это обезличенная учебная адаптация.** Реальные имена доменов, устройств, пользователей, GPO и внутренние пути не публикуются. Исторические снимки в `history/` отключают `Enforce`, а публичная текущая версия требует отдельного подтверждения `-AcknowledgeAppRemoval`. CMD запускает **Audit**, хотя исходная производственная CMD-обёртка использовала **Enforce**.

## Что делает скрипт

- `-Mode Audit` по умолчанию: обнаруживает пакеты и записывает события, ничего не удаляет.
- `-Mode Enforce`: `Remove-AppxPackage` **только** для явно перечисленных имён `Get-AppxPackage` **текущего пользователя**; в публичной версии требуется дополнительный флаг подтверждения.
- Не удаляет provisioned packages, Machine-wide Win32, Microsoft Office desktop, классический Outlook и Skype for Business.
- `NonRemovable`, `IsPartOfSystem`, расположение в `Windows\SystemApps` → `PROTECTED`; никакого принудительного удаления системных каталогов.
- Не запускается под SYSTEM; пропускает Windows Server, если явно не передан `-IncludeServers` (опцию не следует включать без RDS-аудита).
- Использует локальный пользовательский mutex; при работающем `olk.exe` откладывает удаление нового Outlook.
- Обнаруживает отдельный OneDrive Desktop, но удаляет его только при `-Mode Enforce -RemovePerUserOneDrive` и с остановленным процессом; машинную установку не трогает.

## Важные границы безопасности

**Списки приложений не универсальны.** Подтверждённое в конкретном пилоте имя `A025C540.Yandex.Music` не означает, что оно идентично на других ОС/редакциях. Многие имена — кандидаты, которые следует подтвердить инвентаризацией. Удаление компонентов Xbox, Outlook или Microsoft 365 Hub может нарушать пользовательские сценарии.

GPO-область действия задаётся настройками **OU, Security Filtering, наследованием и loopback processing**, а **не проверкой суффикса имени учётной записи внутри PowerShell**. Исключения пользователей необходимо описывать в конфигурации GPO, не вшивать их реальные логины в публичный код.

`Run-AppCleanup.cmd` в продакшен-источнике принудительно включал `Enforce`. Публичный CMD намеренно работает в режиме `Audit`. Этот пример **не является готовым корпоративным скриптом** и не проходил повторные Windows-тесты после обезличивания. Он не создаёт полного удаления предустановленных приложений из образа Windows.

## Структура

- `scripts/Remove-UserApps.ps1` — публичная v1.4 с дополнительным подтверждением перед удалением.
- `scripts/Run-AppCleanup.cmd` — иллюстративный логон-скрипт `Audit`.
- `scripts/Get-AppxCleanupInventory.ps1` — новый вспомогательный инструмент инвентаризации.
- `history/` — обезличенные v1.0, v1.3, v1.4 и соответствующие CMD, историческая `Enforce` отключена.
- `docs/gpo-setup.ru.md` — схема внедрения через пользовательскую GPO.
- `docs/security-review.ru.md` — матрица рисков и проверки.
