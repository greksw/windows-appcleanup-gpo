# Развёртывание через User GPO

Описана **архитектура оригинального кейса**, а не универсальная рекомендуемая политика удаления приложений.

## Назначение

1. Создать **пользовательскую** GPO и привязать её только к согласованным OU интерактивных пользователей. В исходном проекте применялись локальные учётные записи рабочих станций, сгруппированные по OU; в организации были осознанные исключения из схемы именования. Не кодируйте правило «имя оканчивается на 2» внутри скрипта и не переносите исключения вслепую.
2. В `User Configuration → Policies → Windows Settings → Scripts (Logon)` либо через GPP добавить `Run-AppCleanup.cmd`, запускаемый при входе **самого пользователя**, а не SYSTEM. Проверить порядок применения, Security Filtering и наследование OU.
3. Для прототипа использовать только **Audit**, затем изучить логи и перечень фактически найденных Appx, согласовать удаления со службой поддержки/владельцами приложений и провести отрицательные тесты.
4. Если выбран Logon Scripts, GPO отвечает за запуск при входе, а не за выполнение на уже открытых сессиях. Для RDS требуется отдельный аудит и решение; не включать `-IncludeServers` автоматически.
5. Предоставить компьютерным/пользовательским принципалам права чтения скриптов из NETLOGON; строго ограничить права записи. Изменение файла SYSVOL и выполнение PowerShell из общедоступной записи представляет риск исполнения произвольного кода.

## Проверка на клиенте

```powershell
whoami /user
gpresult /scope user /r
Get-AppxPackage | Select-Object Name, PackageFamilyName, NonRemovable
Get-Content "$env:LOCALAPPDATA\Example\AppCleanup\cleanup.log" -Tail 40
```

Лог в публичной версии: `%LOCALAPPDATA%\Example\AppCleanup\cleanup.log`. В оригинале путь другой. Убедитесь, что лог создан в **ожидаемом профиле** пользователя.

## Тестовый ручной запуск

```powershell
powershell.exe -NoProfile -File .\scripts\Remove-UserApps.ps1 -Mode Audit
```

`Enforce` в публичном примере требует дополнительного переключателя подтверждения и не рекомендуется без предварительной адаптации. Не публикуйте реальные логи: они включают имена ПК, локальные имена пользователей, SID и сведения об установленных приложениях.
