# Модель безопасности и известные ограничения

| Вопрос | Реальное поведение исходного скрипта |
| --- | --- |
| Контекст | Текущий пользователь; под SYSTEM выход с кодом 10 |
| Scope удаления | Только Appx текущего пользователя; **без** `-AllUsers` и `-Online -Remove-ProvisionedAppxPackage` |
| Начальный режим | `Audit`, ничего не удаляет |
| Производственный CMD | `Enforce`; в публичном CMD заменён на `Audit` |
| Защищённые компоненты | Пропускает `NonRemovable`, `IsPartOfSystem`, `Windows\SystemApps` |
| Windows Server/RDS | Пропускает без `-IncludeServers`; включать после независимого тестирования |
| Новый Outlook | Если `olk.exe` запущен, удаление откладывается |
| OneDrive desktop | Отдельный флаг и отдельный per-user деинсталлятор; не трогает machine-wide |
| HKCU Uninstall | Только инвентаризация; публичный пример не логирует параметры uninstall-команд |
| GPO область | Вне кода; OU, Security Filtering, наследование и, при необходимости, loopback |

## Операционные риски

- `Microsoft.XboxIdentityProvider`, `Microsoft.OutlookForWindows` и другие пакеты могут требоваться приложениям пользователя; нельзя автоматически считать всякий предустановленный пакет «мусором».
- `Local\<SID>` mutex защищает от повторов **внутри сессии**, но не гарантирует взаимное исключение между разными сессиями того же пользователя. Перед применением в многосессионных средах требуется отдельное проектирование.
- Выход с кодом `0` при пропуске сервера или заблокированном mutex не означает успешного удаления приложений.
- Appx-пакет может быть автоматически восстановлен обновлением Windows или новой регистрацией; `Remove-AppxPackage` не запрещает последующую установку.
- Состав системных Appx и флаги защиты зависят от редакции/сборки Windows. `-IncludeServers` **не** означает пригодность для RDS.
- Существующий сценарий не экспортирует список удалённых Appx для отката. Восстановление следует проверять отдельно и не обещать безусловный rollback.
- Журнал оригинала включает хост/пользователя/SID и настраиваемые команды удаления HKCU; к публикации требуются обезличивание и сокращение логирования.

Публичный вариант обеспечивает защиту от случайного запуска `Enforce`, но она **не является заменой** проверки кода или контроля прав на распространение.
